# transcription-benchmarking

Runs singing transcription systems on the same recordings and scores them the same way. Below are results for 15
published systems and transcPybe on five datasets, how they were obtained, and how to run the benchmark on other data.

## The benchmark

### Which systems

A systematic survey ([`docs/vocal-transcription-tools.md`](docs/vocal-transcription-tools.md)) found 48 candidates.
26 of them were runnable systems that write notes and apply to singing. 11 of those were not run:

- five are other versions of a system that was run;
- two have weights that are not publicly downloadable;
- two do not write timed notes;
- one was not trained on singing;
- one, a 2019 melody extractor, was not pursued.

The survey's [What was run](docs/vocal-transcription-tools.md#what-was-run) table names each one and its reason. That
left 15.

### How they were run

- **Containers.** Each system runs in its own container (`orchestrator/`), built from the authors' code pinned to a
  commit, with their released weights and the network off.
- **Settings.** Published systems run at their authors' default settings. Nothing was tuned on these datasets; where
  a system needed a change to run at all, the change is in its image (`orchestrator/images/`).
- **Scoring.** Every system gets the same audio and writes MIDI, and each recording is scored with this package's
  metrics.

### Datasets and scoring

- **Datasets.** vocadito [16] (40 excerpts, both annotators), Molina [17] (38), SSVD v2.0
  test [18] (127), the RWC-P [19] development half (48 songs with notes) and MIR-ST500 test
  [2] (the 82 of its 100 songs still online). The two pop sets are lead vocals separated with
  BS-RoFormer; every system gets the same stems.
- **Score.** COnPOff@50 at whole semitones [17]: onset within 50 ms, pitch within 50 cents, offset within
  20% of the note's length or 50 ms. Macro-averaged over recordings. *A cappella* averages vocadito (its two annotators
  averaged), Molina and SSVD; *pop* averages RWC-P and MIR-ST500; the five-set mean averages all five.
- **Intervals.** 95%, paired bootstrap over recordings, stratified by dataset, 10,000 resamples, seed 0.
- **Time.** Seconds of computation per minute of audio, model loading included, on 10 Molina recordings and 2 RWC-P
  songs (12.1 min), on 8 cores of an AMD Ryzen 9 5900X, with (GPU) or without (CPU) an NVIDIA RTX 3080. –: not run on
  that device (no GPU path in the package or image, or a GPU is required).

## Running it on other data

### Score a system's output

```shell
pip install -e .
transcription-benchmark AUDIO_DIR --annotations ANNOTATION_DIR --estimates OUTPUT_DIR -o results/system.json
```

`OUTPUT_DIR` holds one MIDI or CSV file per recording, matched to the audio by name. The report gives COn, COnP and
COnPOff with 95% intervals from a bootstrap over recordings.

Two checks are worth running first:

- `--inspect DATASET` shows what the loader made of the annotations: whether a column is an offset or a duration, and
  whether pitch is MIDI or Hz.
- `--dry-run` shows which annotation was paired with which recording, without reading any audio.

### Compare two systems

```shell
transcription-benchmark --compare a.json b.json
```

This bootstraps the paired difference over the recordings both runs share. Two overlapping intervals do not mean two
systems are level; this does tell you. `--by-metadata FILE:COLUMN` breaks the comparison down by a column of a
metadata CSV, such as language.

### Run every system on your data

```shell
cd orchestrator
./bench.py all --audio AUDIO_DIR -a ANNOTATION_DIR
```

This builds each system's image, transcribes, scores and compares. `--only game,basic-pitch` restricts it to named
systems. Setup (Docker, the NVIDIA Container Toolkit, about 35 GB of images, and the checkpoints that need a manual
download) is in [`orchestrator/README.md`](orchestrator/README.md).

### Add a system

A system that writes MIDI or CSV needs no code: run it, then pass its output directory to `--estimates`. To have the
benchmark call it directly, with results cached on its settings, register an adapter in its package:

```toml
[project.entry-points."transcription_benchmarking.transcribers"]
mysystem = "mypackage.adapter:MySystem"
```

```python
class MySystem:
    def transcribe(self, audio: Path) -> Sequence[tuple[float, float, float]]:
        """(onset seconds, offset seconds, MIDI pitch) per note."""

    def settings(self) -> dict:
        """Optional: recorded with the result, and the cache key."""
```

`--list-transcribers` shows what is installed; `--transcriber NAME` runs one.

### Options for other datasets

| Option | For |
|---|---|
| `--annotations-json FILE` | One JSON for the whole corpus, keyed by recording (as M4Singer and MIR-ST500 ship). |
| `--pairs FILE` | An explicit audio-to-annotation CSV, where names do not match. |
| `--annotation-contains TEXT` | Choosing among several annotations of one recording. |
| `--items FILE` | Restricting to a published split. |
| `--sample N` | N recordings drawn across the corpus, rather than the first N. |
| `--align` | References notated at a nominal tempo: each is warped onto its recording's pitch contour. |
| `--onset-shift SECONDS` | References that start a note at a different point, such as the consonant. Only estimated starts move. |
| `--time-offset SECONDS` | References offset from their audio by a constant. |

The last three are corrections. Each is recorded in the result and printed in the report. The table above uses none
of them.

### The ceiling

```shell
transcription-benchmark vocadito/annotations --agreement notesA1 notesA2 -o ceiling.json
```

This scores one annotator against another. On vocadito, the two agree at COn 0.817, COnP 0.740 and COnPOff 0.642. The
last figure matches the 0.64 the vocadito paper reports.

## Reproducibility

Every result records:

- the system and its settings;
- the seed;
- the versions of the packages that matter;
- this repository's commit;
- a SHA-256 digest of the dataset files.

The results table is regenerated from `scripts/scores.json` (every row's COnPOff@50 per recording) and
`scripts/timing.jsonl` by `python scripts/readme_results.py`, and a test fails if the README and those files disagree.
`python scripts/results_table.py --tests` prints the paired tests between neighbours in the ranking.

`--cache-dir` reuses transcriptions, keyed on the system's settings. If you tune a system on a dataset, its score
there no longer estimates performance on unseen recordings, so report on another dataset or on a held-out split.

## Install and tests

```shell
pip install -e .    # Python 3.9 or newer; no transcriber is a dependency
pytest -q
```

## Credit

The metrics are computed with [mir_eval](https://github.com/mir-evaluation/mir_eval) (Raffel et al., ISMIR 2014).
[librosa](https://librosa.org/) (McFee et al., SciPy 2015) provides audio loading, pYIN and DTW, and
[pretty_midi](https://github.com/craffel/pretty-midi) (Raffel and Ellis, ISMIR 2014) reads MIDI. No dataset is
redistributed here.
